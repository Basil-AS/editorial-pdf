# Сборка A4 по ГОСТ 7.32

Зависимости: Pandoc 3.1+, XeLaTeX с пакетами шаблона, fontconfig, Python с pypdf и PyMuPDF, Poppler. Markdown и LaTeX-формулы должны быть доверенными.

    python scripts/norms.py plan review.json --kind "Отчёт о НИР"
    # Заполни решения по стандартам, причину и прочитанные страницы.
    python scripts/norms.py check review.json
    python scripts/build_pdf.py report.md -o report.pdf --front-pdf title.pdf --review review.json
    python scripts/verify_pdf.py report.pdf --hidden 1
    pdftoppm -r 110 -png report.pdf /tmp/report-page

В полном отчёте передай готовый титул по ГОСТ 7.32 через --front-pdf и поставь пустой блок .front первым. Добавь реферат, введение, основную часть, заключение и применимые структурные элементы. Для фрагмента используй --draft. --font выбирает шрифт с кириллицей, по умолчанию Times New Roman. Основной кегль по умолчанию — 16 pt; --body-font принимает 12, 13, 14 или 16. Табличный кегль по умолчанию — 14 pt; --table-font 12 оставлен для особо плотных таблиц. --numbering section включает нумерацию по разделам. --hidden соответствует фактическому количеству начальных листов без номера.

- Для заголовка задавай ASCII-ID, например # Методика {#method}. Номера добавляются автоматически. Для дополнительного структурного заголовка задай .unnumbered. Заголовки уровней 1–3 автоматически входят в закладки PDF. Печатное содержание не выводится по предпочтению владельца этого профиля. ГОСТ 7.32 допускает его отсутствие в отчётах до 10 страниц включительно; для более длинного отчёта зафиксируй отступление в `review.json` и не заявляй полное соответствие стандарту по составу. Пустой блок .toc необязателен и только добавляет закладку «Структура документа».
- Маркированный Markdown даёт тире, нумерованный — цифры со скобкой. Для кириллических меток оберни нумерованный список с 1 в .lettered. Пунктуацию расставляй в исходнике.
- Оберни таблицу с подписью Pandoc в {#tbl-results .table}. Подпись начинается с «: ». Короткие таблицы занимают ширину по содержимому; длинные ячейки переносятся, а слишком широкая таблица ограничивается полосой набора. Ячейки по умолчанию выравниваются влево; числовым столбцам задай нужное выравнивание в Markdown. Для сложных объединённых ячеек и многоуровневых шапок применяй отдельную вёрстку. Автоматический перенос повторяет шапку и строку продолжения.
- Вставь отдельный абзац ![Схема проверки](diagram.pdf){#fig-flow}. Поддерживаются локальные PDF, PNG и JPEG. SVG заранее экспортируй в векторный PDF.
- Помести формулу $$...$$ в {#eq-id .equation}. Для ссылок используй [в формуле (1)](#eq-id). Аналогично ссылайся на таблицы, рисунки и заголовки. Проверяй видимые номера после перестановок.
- Для источников используй .sources с одним нумерованным списком с 1. В тексте ставь [\[1\]](#ref-1).
- Для приложения используй # Материалы испытаний {#app-a .appendix letter="А" status="справочное"}.
- Для альбомного блока используй .landscape. Если вкладываешь таблицу и другие блоки, внешняя ограда должна иметь больше двоеточий.

~~~markdown
::: {.toc}
:::

# Методика {#method}

Результаты приведены в [таблице 1](#tbl-results). Проверка включает:

::: {.lettered}

1. регистрацию события,
2. проверку результата.

:::

:::: {.landscape}

::: {#tbl-results .table}

| Показатель | Значение |
|------------|----------|
| Проверка   | Пройдена |

: Результаты проверки

:::

::::

# Материалы испытаний {#app-a .appendix letter="А" status="справочное"}

Описание материалов.
~~~

Проверь конечные точки, номера, реквизиты, ссылки, читаемость схем и границы таблиц визуально. Скрипт проверяет лишь часть требований.

## Учёт всего комплекта

Перед работой проверь каталог и целостность всех источников.

    python scripts/norms.py catalog
    python scripts/norms.py verify-sources
    python scripts/norms.py search "Таблицы" --id gost-r-2-105-2019
    python scripts/norms.py read gost-r-2-105-2019 --pages 14-16

Номера в read — физические страницы PDF. Поиск возвращает фрагменты для навигации. Для решения прочитай пункт с его исключениями целиком и сверяй иллюстрации с оригиналом.

Файл review.json содержит решение по всем 21 источникам и проверкам из памятки. Для apply заполни reason, read_pages и статусы checks. Для not_applicable обоснуй решение и укажи not_applicable у проверок. После создания PDF впиши свидетельства выполнения, затем запусти:

    python scripts/norms.py check review.json --final

Полная сборка требует --review с принятыми решениями. Технический прогон --draft разрешён без записи. Для других видов документов базовый сборщик отклоняет несовместимые выбранные профили. В приложении отчёта программный ТЗ сверстай отдельно с собственной структурой и корректным включением в комплект.
